# Architecture

The one-page version is [architecture-one-page.md](architecture-one-page.md). This document is for people changing cstack.

## Split of responsibilities

| Part | Deterministic or judgment | Lives in |
|---|---|---|
| Skills | judgment, constrained | `skills/<slug>/SKILL.md`, `skill.meta.json` |
| Shared rules | both | `skills/cstack-shared/PREAMBLE.md` (`cstack preamble`) |
| CLI | deterministic | `bin/cstack.mjs` → `scripts/lib/*.mjs` |
| Providers | I/O | `providers/*.mjs`, `registry/providers.json` |
| Browser | I/O | `scripts/lib/browser/*.mjs` (from gstack, MIT) |
| Craft checkers | deterministic | `scripts/lib/{type,svg,mockup,three,video}/` (`cstack type`, `svg`, `mockup`, `3d`, `video`), loaded on demand |
| Flows | method | `flows/*.flow.yaml` (library, dated); a run's plan in the workspace `work/flows/` |
| Schemas | contract | `schemas/*.schema.json` (generated by `scripts/dev/gen_schemas.py`, except `common`) |
| Registries | dated facts | `registry/models.json`, `research-tools.json`, `hosts.json`, `skills-index.json` (generated) |
| Canon | mental models | `canon/*.canon-entry.yaml` |
| Workflows | orchestration | `workflows/<name>/workflow.yaml`, run by the `workflow` skill |
| Evals | protection | `evals/fixtures/*.yaml`, `tests/*.test.mjs`, `scripts/lib/evalplan.mjs` |
| Brand data | never here | each brand's own workspace repo, created from `templates/brand-workspace/` |

The rule of thumb: if a step can be exact, it is code in `scripts/lib`; if it needs taste, it is a skill; if it needs a person, it is a gate.

## Core flows

**Method before making.** No outcome is one-shot (preamble 0.5). The agent states the target, then `cstack flows search "<outcome>"` finds a researched flow (library `flows/` plus the workspace's own `flows/`, where a same-id workspace flow wins). A stale or missing flow sends the agent to `/flow-research`, which compares at least two ways of reaching the outcome from current evidence. `cstack flows plan <id> --target "..."` copies the flow into `work/flows/`, and `cstack flows check` refuses a plan that compared fewer than two candidates, left a step without a gate, made something without saying how it is compared to the target, has no stop condition, or still carries the library's target wording. The plan then runs one step at a time, and what worked goes back into the flow (`runs`, `evidence`) through `learn-loop`.

**Brand truth write.** `cstack brand set section.field --file f.json` → `applyToBrand` compares source rank (precedence below) → higher wins, equal-and-different becomes a conflict entry, `locked` fields refuse non-owner writes → artifacts whose lineage referenced the field are listed as stale (`cstack brand stale`).

```text
user_instruction > approved_brand_state > official_asset > live_brand_behavior
> campaign_exception > extracted_pattern > external_reference > model_inference
```

**Brand context for a prompt.** `cstack brand context --sections a,b` returns only fields whose approval is locked, current or testing, a `not_facts` list (inferred, unknown), open conflicts and a hash. Keys are sorted so the output is byte-stable and works as a cached prompt prefix. Skills ask for the sections they need, never the whole system.

**Generation.** Prompt recipe (`prompt-recipe` schema: slots, model syntax, stable prefix) → `cstack prompt compile` (deterministic, hashed) → `cstack route` picks a model from `registry/models.json` (modality, needs, status, staleness, unit cost, owner preference) → `cstack spend plan` estimates the batch and requires a stop condition → `cstack generate` calls `guardedCall`:

```text
hash(request) already done?  → reuse output, no charge
over per_run / per_day / confirm_over? → block, ask owner
submit → persist pending job id → poll → download → .gen.json sidecar → size audit → ledger row
timeout → job stays pending; `cstack jobs` resumes it; never resubmits
retry only on transient errors
```

**Judgment.** Deterministic gates first (tokens lint, size audit, browse QA, claims list), then an independent verifier (different model, provider verifier, or fresh context with only brief + brand context + artifact), then the owner. Every verdict is an `eval` record with evidence; owner choices are `feedback` events and outrank judges.

**Learning.** Events append to `state/*.jsonl`. `cstack learn candidates` surfaces learnings with repeated evidence or a strong owner correction. `cstack learn promote <id> --to <target>` moves one to brand state, a rule, a token, a fixture or a skill, keeping provenance. Encode at the lowest reliable level: tokens > components > rules > agent rules > exemplars > learned preferences.

**Experiments.** `cstack experiment init|log|status` implements bounded keep/discard loops (autoresearch style): one mutable surface, a frozen fixture, a fixed budget, regressions checked, an incumbent that only changes on evidence, and explicit stop conditions.

## Skills

Each `SKILL.md` has frontmatter (`name`, a description with "Use when" and "Not for", `license`, `metadata`) and the contract headings `cstack validate` requires: when to use, when not, inputs, missing-input behavior, source precedence, tools/providers, process, decision rules, outputs, evals, handoff, failure modes, examples. `skill.meta.json` carries type (capability, composite, playbook), triggers, inputs, outputs, handoffs, approval gates, fallback mode, cost class, budget, compatible hosts and eval fixtures. `cstack index` generates `registry/skills-index.json`; `cstack validate` fails when it drifts.

Context budgets are measured, not guessed: each skill and the catalog have token budgets that `cstack budget --check` enforces in CI and `--ratchet` tightens after a skill shrinks.

`cstack setup` installs the same canonical skills into each host's directory (`registry/hosts.json`) by symlink, or copy with `--copy`; it never overwrites a non-link directory.

## Evals

| Tier | What | Cost |
|---|---|---|
| T0 | static: schemas, contracts, index, links, budgets, hygiene | free, every commit |
| T1 | deterministic behavior: router, tokens, browser fixtures, lints | free, every commit |
| T2 | single-skill fixtures with a model in the loop | small, when the skill or its deps change |
| T3 | multi-skill / workflow fixtures | moderate, before release |
| T4 | end-to-end workflow on the example brand, owner-graded | release |

`cstack evals plan --since <ref>` maps changed files to the fixtures that can be affected (skill dependencies, `depends_on`, shared files) so a PR only pays for what it can break. Fixtures declare `cannot_isolate` when a behavior can only be judged in a larger run.

`cstack validate` also checks that fixtures follow the documented format (tier, grader types and fields, patterns that compile in JavaScript, known skills) and that every `cstack <command>` named in skills, docs, fixture graders and flow gates exists, so instructions cannot drift ahead of the code. A command that is only planned must say so on the same line.

## Research tools and MCPs

`registry/research-tools.json` lists each tool's access mode (API, MCP, browser-only, owner-export-only, human-only), detection signals, fallback and the skills that use it. `cstack tools` reports availability from MCP server names the agent passes (`--mcp` or `CSTACK_MCP_SERVERS`), MCP config files, env var presence (values never printed) and CLIs on PATH. Tools are capabilities, never dependencies.

## Browser

`cstack browse` is a one-shot port of gstack's browse layer on `playwright-core`: no daemon, no cookie import, no tunnels, no stealth. Navigation is locked to the target origin; private and metadata addresses are blocked; logout and destructive links are refused; mutations on non-local origins need `--allow-mutation`; page text is wrapped as untrusted. Every run writes `work/browse/<run-id>/run.json` with hashes. See `NOTICE.md` for attribution.

## Security model

- Credentials only from env vars named in `registry/providers.json`; job IDs persisted, keys never.
- Spend blocked by default; dry runs and estimates before batches; dedupe prevents paying twice.
- Official assets immutable; outputs go to `work/`.
- Everything fetched is untrusted data, and so is text inside files: glTF extras and names, SVG metadata, font names, video tags. Checkers print such text inside an untrusted block and never act on it.
- Hygiene checks in `cstack validate` look for secrets and brand-specific material in tracked files.
