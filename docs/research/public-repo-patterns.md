**Method.** I read repository mechanics, not READMEs: agent guidance files, skill layout, metadata and schemas, generators, validators, CI workflows, provider adapters, retry code, cost code, state files and recent `git log`. Every claim cites `repo/path:line` under `/home/claude/research-src/`. Where I ran a check myself (for example counting broken index entries), the command is described inline.

## 1. gooseworks-ai/goose-skills (fresh)

**What it is.** An npm-installable catalog (`npx goose-skills install <slug>`). Skills live at `skills/<domain>/<level>/<slug>/`, where level is one of `capabilities | composites | playbooks`. Each skill has a `SKILL.md` plus a `skill.meta.json`. Packs live at `skills/<domain>/packs/<pack>/`. Editorial collections live at `collections/<slug>/`. A generated `skills-index.json` feeds a private backend DB sync.

**Key mechanisms**

- **Three abstraction levels, encoded as folder names and enforced.** `scripts/validate-skills.js:12` lists the levels as `['capabilities','composites','playbooks']`. `:115` fails if `meta.category` differs from the folder. The schema enum is at `schemas/skill-meta.schema.json:8`. Current counts: 210 capabilities, 76 composites, 7 playbooks (computed from `skills-index.json`).
- **Human SKILL.md plus machine `skill.meta.json`.** The schema (`schemas/skill-meta.schema.json:1-60`) has these fields:
  - required: `slug`, `category`, `tags` (enum), `installation.base_command`, `installation.supports` (one of claude, cursor, codex)
  - optional: `requires_skills`, `requires_tools`, `example_prompt`
- **Generated index plus a CI freshness gate.** `.github/workflows/ci.yml` runs three steps in order:
  1. `validate-skills.js`
  2. `build-index.js`
  3. `git diff --exit-code skills-index.json`

  The full algorithm is in section 13.
- **Index only includes git-tracked files.** `scripts/build-index.js:26-46` runs `git ls-files`, so local eval captures and SkillOpt outputs never leak into the index. The backend would otherwise 404 when it fetches those paths.
- **Reproducible generated date.** `build-index.js:401-417` keeps the old `generated` date when nothing else changed, so CI does not see a spurious diff.
- **Tree ⊆ index check.** `validate-skills.js:144-180` walks the tree. Every `SKILL.md` on disk must appear in the top-level `skills[]`. Nested presence in a pack does not count. The motivating regression was pack sub-skills being invisible to the backend.
- **Routing has one source of truth, with a drift test.** `collections/brand-growth/collection.meta.json` declares `routes.$ref: ./routes.json`, which mirrors `gooseworks/src/skills/routes.ts` in another repo. `test/brand-growth-routes.test.js:1-60` fails when the mirror and the skill membership disagree. This replaced "three hand-synced places" (`:4-9`).
- **Paid-media proxy helper (`media_proxy.py`).** Its docstring is at `skills/ads/capabilities/media-proxy/scripts/media_proxy.py:1-55`.
  - **Billing attribution.** Every call goes through the GooseWorks proxy with `token`, `agent_id` and `project_id`, so spend lands on a project (`:1-12`).
  - **Idempotency.** `input_digest(model,args)` (`:163-179`) is the sha256 of canonical JSON `{model,args}`, first 32 hex characters. It is sent as `idempotency_key` and as the `x-gw-input-digest` header (`:377-391`). A resumed run re-attaches to the paid job instead of paying twice.
  - **Crash-resume.** A pending job `{request_id,status_url,response_url,project_id,ts}` is persisted to `~/.gooseworks/pending-fal-jobs/` at submit time (`:239-273`). `resume_fal(request_id)` re-attaches later (`:429`).
  - **Poll timeout never resubmits.** `FalPollTimeout` (`:289-333`). The comment records the incident: a lipsync job finished at 626s, a 600s poller gave up, and the retry paid for a duplicate job. Video gets a 1800s poll timeout, images 600s, chosen by model-name hints (`:300-318`).
  - **Transient vs real errors.** Polls retry through `ConnectionError`/`Timeout` (`:244-287`). Provider error bodies (content-policy, NSFW, quota) are surfaced as `RuntimeError` and never retried (`:218-236`).
  - **Diagnostics.** `gw_log` is a fire-and-forget run log with typed events: `generation | api_failure | missing_input | confusion …` (`:181-215`).
  - **MCP relay with no local credentials.** The script writes the exact tool call to `working/mcp-requests/<kind>-<hash>.json` and exits with code 3. The agent makes the call and re-runs the script (`:35-42`).
- **Vendored copies drift by design.** `media_proxy.py` exists in **12 copies**, all md5-identical today (checked). A commit message records the manual sync: "sync all 9 media_proxy.py copies" (git log 2026-09-29). No test guards that the copies stay identical.
- **Gate mutation testing ("falsify").** `skills/ads/capabilities/render-street-interview/scripts/falsify-all.py:1-25` plants a fault for every check in the QC gate and asserts that the gate names it. Its docstring records two checks that "passed vacuously on every input for their whole life".
- **Release provenance for a generated package.** `skills/ads/playbooks/video-production-harness/release.json` records `source_commit`, `source_hash`, and per-file `sha256`/`bytes`. `test/shared-video-harness.test.js:11-27` re-hashes every file. `:36-40` greps shipped sources for private leakage: `mcp__`, `/Users/`, `GOOSEWORKS_*`.
- **Deterministic ship gate for research output.** `skills/ads/composites/brand-research/scripts/verify_pack.py:1-40` requires fixed headers per file (for example `visual-identity.md` must have "Primary colors (hex)" and "Off-limits styles"). It exits non-zero on drift.
- **Local eval harness.** `test/TESTING.md:1-50` and `schemas/eval.schema.json` define:
  - a per-case `manifest.json` envelope: `{messages, artifacts[], side_effects[], tool_calls[], cost_usd}`
  - a `--budget` USD cap
  - a `safety.mutatesExternalState` flag that fails runs outside a sandbox
  - human 👍/👎 labels that calibrate the judge
- **SkillOpt loop.** `skillopt/README.md` uses this vocabulary: student, tutor, judge, examiner, with train/val/test splits. A rewrite is kept only if the held-out split improves. Questions are generated from the skill's contract, never its method.
- **Authoring rule forced by the infrastructure.** `CONTRIBUTING.md:5`: SKILL.md bodies are replayed through a WAF, so the prose must avoid shell variables, absolute paths and install commands.
- **Release.** Changesets publish to npm on push to main (`.github/workflows/release.yml`). A repository dispatch then syncs a private app (`dispatch-private-sync.yml`).
- **Cost guard for scrapers.** `tools/apify_guard.py:1-40` has a module-level run counter (default limit 50), an optional confirm prompt, and proxy routing when `GOOSEWORKS_API_KEY` is set.

**Recent commits show what broke.**

- "description colon breaks the catalog sync" (2026-10-01)
- "make the index reproducible off Linux" (2026-10-01). Windows path separators had emptied `files` (`build-index.js:66-71`).
- "poll timeout never resubmits" (2026-09-28)
- "fix guards that rejected everything" (2026-09-29)
- "banned phrases match word forms, not stems" (2026-10-01)

**Mechanisms**

- **Sidecar provenance per artifact.** `animated-explainer-ad/scripts/lib.py:43-47` `write_meta()` writes `<file>.meta.json` with `created_at`. Callers add more fields:

  - `render_clip.py:116-124`: `duration_requested`, `duration_actual`, `resolution`, `provider`, `keyframe`

  **No seed and no cost** are recorded.
- **Phased pipeline with human gates and an autopilot escape hatch.** `scripts/auto.sh:1-45` warns that the autopilot "pays for clips before catching character drift". It prints the estimated cost (~$15-25) and waits for Enter.
- **Credentials.** `.env` lives in the skill folder. `require_env()` exits with instructions (`lib.py:27-31`). `FAL_API_KEY` is aliased to `FAL_KEY` (`:22-24`).
- **Docstring vs code.** `lib.py:3-4` claims "HTTP retries", but the 72-line file has no retry helper.

## 3. Superside/comfyui-superside-nodes (fresh)

**What it is.** A ComfyUI custom-node package. Model nodes share mixins in `modules/base_node.py`. Local nodes (crop, stitch, colour match, white balance, normalize) use no API. There are no tests and no CI. The README holds a changelog.

**Mechanisms**

- **Prompt Slots** (`modules/prompt_variants_node.py:126-205`).
  - One long template with `{key}` placeholders and 4 key/slot pairs.
  - An unconnected slot whose placeholder is present is **removed** from the text, with a note (`:186-192`).
  - A connected slot with no placeholder produces a note (`:193-195`).
  - Leftover `{x}` tokens are noted and **left in the text** (`:199-200`).
  - Everything is reported on a second `info` output.
  - **It warns. It does not fail.** This is a deliberate choice (`:135-138`): "a wire that silently does nothing is the failure worth catching". Here, "catching" means surfacing it.
- **Prompt Variants** (`:39-123`).
  - The pool is split on lines that are exactly `---`. An optional `# label` line names a block (`:16-36`).
  - Three modes: `random` uses `random.Random(seed)`, `cycle` uses `seed % count`, `fixed` uses a clamped `index` (`:115-120`).
  - The node returns `(text,label,index,count)`, so the workflow records which variant ran. The docstring notes "no counter hidden in the node" (`:52-55`).
  - Empty pools raise (`:108-112`).
- **Retry only transient errors** (`base_node.py:369-482`). `TRANSIENT_MARKERS` are substring matches on 502/503/504, "downstream service unavailable", "server disconnected", and similar (`:373-392`). Backoff is `(5,15,30)` seconds (`:394`). Validation, auth and policy errors fail immediately because they are not on the list (`:445-449`).
  - **Risk.** It also retries "server disconnected" on the *synchronous* path (`:388-392`). That can re-run a job that is already billed. goose-skills explicitly forbids this (section 1).
- **Queue for slow endpoints.** `QUEUED_ENDPOINTS` (`base_node.py:69-75`) use `client.subscribe` with a 1200s client timeout (`:77-81`). A log filter drops ~700 "still queued" poll lines per call (`:20-49`).
- **Resolution audit** (`_check_returned_size`, `base_node.py:247-307`).
  - If the aspect ratio drifts by more than 4%, it **raises**: the image was reframed, not resized.
  - If the area falls below 50%, it **warns**. The area check is deliberately non-fatal because one pipeline renders small on purpose.
  - Between 50% and 95% area, it logs an info message.
  - The incident: a 3712×4608 source came back at 736×896 "and nothing said so" (`:247-249`).
  - A bug fix: the endpoint is passed as a parameter, because reaching for `self.ENDPOINT` raised inside the guard (`:269-274`, commit "Size guard: name the endpoint…").
- **Cost ledger.** One choke point covers every node (`_record_cost`, `base_node.py:415-439`).
  - The price table carries a `SOURCE_DATE` (`modules/fal_pricing.py:1-26`) and two kinds of entry: **priced**, with an estimator built from args and response, and **unpriced**, with a reason.
  - `MANUAL_PRICES` holds prices measured by hand and labelled as such (`:520-536`).
  - Unknown or failed prices give `usd=None` plus a reason, and **are never guessed** (`:550-605`).
  - The report says "The total above EXCLUDES those calls" (`fal_cost_ledger.py:150-160`).
  - `--check` re-reads fal's catalogue and diffs the *amount sets*, not the prose (`fal_pricing.py:~700`).
  - The ledger lives only in memory. It resets on restart and is capped at 5000 entries (`fal_cost_ledger.py:8-25`).
  - Prices are drawn on the node itself (commit 2026-09-09).
- **Simple creative dials mapped to tested bundles.** `scene_realism_prompt_node.py:20-61`: 5 levels, each mapping to a `(prompt_fragment, lora_scale, strength)` table. Unknown levels fall back to the default (`:106-108`).
- **Exact deterministic compositing.**
  - `stitch_region_node.py:11-28` resizes the generated crop to *exactly* the recorded box, then feathers the paste with colour decontamination.
  - `normalize_product_node.py:24-35` places the product in a fixed frame with "No AI, no API key".
- **Credentials.** A per-node `api_key` input. The `FAL_KEY` env fallback is opt-in and documented as safe only on single-tenant setups (`base_node.py:84-125`).

## 4. yc-software/qm (fresh, very active)

**What it is.** A generic agent platform. All org specifics live in a deployment directory that the `qm` CLI validates and deploys (`README.md:102-106`).

**Mechanisms**

- **One guidance file for every host.** `CLAUDE.md -> AGENTS.md` is a symlink (checked with `ls -la`). `AGENTS.md:125-128` says to replace the symlink only "in the commit that introduces the deviation".
- **Durable by default** (`AGENTS.md:115-123`). Anything read back later (audit, logs, resolved config, queues) must be in Postgres. RAM is allowed only as a cache or for re-derivable state.
- **Generic core plus deployment layer, with pinned upgrades.** A package deployment pins `@yc-software/qm`. An upgrade means: bump the exact dependency, review contract changes, then validate and deploy (`README.md:225-235`). Source forks use `update-qm` and keep merge ancestry (`AGENTS.md:96-106`). The CLI command `check` "validate[s] config + sandbox/ (skills & tools); no build" (`cli/src/cli.ts:134`).
- **Skill lifecycle: scopes plus review.** `src/skills/skill-store.ts`:
  - status is `draft | reviewed | published | archived` (`:8`)
  - editing a non-personal skill resets it to `draft` and bumps `version` (`:211-212`)
  - `publish` refuses a draft (`:242`)
  - `promote` copies only published skills with a valid signature into a target scope (`:285-300`)
  - resolution walks ordered scopes; the first published match wins and the rest are reported as `shadowed` (`:116-125`)
- **Skill pack registry** (`docs/skill-registry.md:1-60`).
  - Packs are pinned to a git `ref`. Update means bump the ref and re-import, which is idempotent.
  - One general normalizer (`src/skills/normalize.ts`) handles any repo's frontmatter dialect through `fieldOverrides`, with "no per-repo code".
  - Exclusion reasons are visible in the catalog: `scope`, `private`, `collision`, `binary-asset`, `malformed`.
  - `declaredCreds` are inferred from `${ENV}` references in the body when not declared (`normalize.ts:69-74,107-108`).
  - Skill files are laid into a per-turn directory that is wiped at turn end. That way, revoked content cannot outlive the turn.
- **Frontmatter parser handles block scalars.** `src/skills/frontmatter.ts:49-60` handles `>`, `|`, `>-` and `|-`. Compare goose-skills, whose index has 105 descriptions stuck at the literal `">"` (section 13).
- **Memory records carry provenance.** `docs/memory-records.md:1-45`: stable IDs, sensitivity labels, source scope/session, and a `sourceUnknown` flag. Consolidation only merges facts with identical provenance. "Runtime context supplies source … never model-authored source claims."
- **Model gateway behind an interface.** `docs/model-gateway.md:1-12`:
  - models are discovered via `/v1/models` plus `/model_group/info`
  - only models with pricing and context metadata are offered
  - the protocol is chosen "from provider metadata, never model names"
  - after a successful discovery, a failed refresh disables gateway routes and fails closed
- **CI mechanics.** `.github/workflows/cicd.yml`:
  - **Reuse exact tested tree.** `scripts/reuse-ci.ts:25-60` re-uses PR CI results when the merge commit's tree equals the tested tree.
  - 5-way test sharding with a shard-plan check.
  - A job that rejects AI co-author trailers (`cicd.yml:178-210`).
- **Review rule.** Never merge without a fresh-context reviewer. Depth scales with blast radius, "judged by checking callers" (`AGENTS.md:40-56`).

## 5. higgsfield-ai/skills (fresh)

**What it is.** Eight `higgsfield-*/SKILL.md` folders. Every action goes through one vendor CLI. Plugin manifests exist for Claude, Codex and Cursor.

**Mechanisms**

- **One adapter binary owns the plumbing.** `CLAUDE.md` "API conventions": "Do not call `api.higgsfield.ai` directly." The CLI handles auth, retries, polling, schema validation and uploads. Credentials come from device-flow login into `~/.config/higgsfield/credentials.json`.
- **Live catalogs, never embedded ones.** `higgsfield model list`, `workflow list` and `preset list` are the source of truth. Reference files are "mappings (intent → command), not the database" (`CLAUDE.md` "API conventions").
- **Route by mode or task, with a small default set.** The `higgsfield-generate/SKILL.md:1-20` description names a default model per task. Commit "narrow automatic model picks to a small default set" (2026-09-26).
- **Chaining through explicit return values.** soul-id returns a `reference_id`, which generate consumes as `--soul-id` (`CLAUDE.md` "Skill chaining"). The rule: finish one skill's questions before starting the next.
- **Dependency-aware revisions** (`higgsfield-brandkit/scripts/brandkit.py`).
  - State is one JSON file, written atomically via temp file plus `os.replace` (`:139-150`).
  - Each slot (`logo`, `palette`, `typography`) carries a `revision`.
  - Each approved brandbook element stores `dependencies: {logoRevision, paletteRevision, …}` taken from its `required_slots` (`:519-552`).
  - Re-saving a slot removes and returns every element that depends on it (`invalidate_brandbook`, `:325-337`).
  - A new palette also invalidates a *generated* logo (`:362-369`).
  - User-supplied "authoritative" slots cannot be overwritten by generated approvals (`:343-351`).
  - Every approval requires an `approval_summary` (`:352-355`).
  - `references/brand-lock.md:170-178` tells the agent to regenerate only the returned dependents.
- **Context discipline.** "The 300-line rule" (`CLAUDE.md:101`) says decision-relevant content stays in SKILL.md and everything else goes to `references/`.
- **CI** (`.github/workflows/validate-skills.yml`) checks:
  - frontmatter via real YAML: name equals the directory, version is present, description ≤1024 characters and contains both "Use when" and "NOT for" (`:49-78`)
  - a repo-wide `VERSION` matching 8 SKILL.md files plus 4 plugin manifests (`:82-112`)
  - every skill listed in the marketplace (`:114-126`)
  - every `references/*.md` link resolving, with no orphans (`:128-153`)
  - no `../` paths (`:155-172`)

  CI runs only when paths change (`:4-20`).
- **Self-contained over DRY.** "Drift between skills is acceptable" (`CLAUDE.md:127`). Duplicated reference docs are a deliberate choice for standalone install.
- **Evals are manual.** `evals/README.md`: "There is no automated runner yet". It has 10 scenarios, a rubric, and a spreadsheet. A "Key Decisions (Do Not Revisit Without Data)" block requires "X over Y because Z% on metric M across N runs". It is currently empty (`CLAUDE.md:170-174`).

## 6. Taste-AI/skills (fresh, prompt-only)

**What it is.** Three SKILL.md files plus one template. No code, no CI, no tests, no schemas. All capability lives behind the remote MCP `https://mcp.tastelabs.com/mcp`, reached by OAuth or a `taste_` API key (`README.md:33-60`).

**Mechanisms (instruction-level only, because there is no code)**

- **Tool capability vs skill judgment.** The README tells users that `npx skills add` installs "the **instructions**, not the tools" (`README.md:35-37`). Each skill names which MCP tools it drives.
- **Evidence lock, then build from one file.** `skills/taste-director/SKILL.md:15-20`:
  1. study references
  2. record every value with its role and source in `BRAND.json`
  3. "close the references and build only from `BRAND.json`"

  Rank determines authority. The top 2 results per query are evidence, results 3-6 are an "inspiration shelf" (`:44-50`).
- **BRAND.json is shaped like the engine's extraction schema.** `brand-template.md` says to fill the same `design_system` shape the extractor returns, with no custom top-level keys. Provenance goes in existing `notes`/`description` fields. "A taste value without a citation … verify treats it as undecided."
- **External verifier with a bounded loop.** `skills/brand-adherence/SKILL.md:129-150`:
  - `verify_brand_adherence(reference_url, candidate_url)` returns a 0-1 `score` that blends an LLM judge with deterministic checks
  - the loop runs exactly twice; any third round is the user's call ("spends them on your blind spot")
  - if the page cannot be reached, never substitute your own impression for the verdict (`:133`)
- **Tool-name version drift is handled in prose.** The README lists old names ("an older server may expose these as `submit_brand` / `get_submission` …").

## 7. rampstackco/claude-skills (active)

**What it is.** 103 knowledge skills (`skills/<name>/SKILL.md` plus `references/`) and 15 workflow templates. Distribution builds for Codex and Pi are committed under `dist/`.

**Mechanisms**

- **Checksum lockfile for the catalog.** `tools/gen_skills_lock.py:1-54` writes a sha256 for every file under each skill, as sorted JSON. CI runs `--check` and exits 1 on any byte diff (`.github/workflows/skills-lock.yml`).
- **Generated host distributions with a drift guard** (`scripts/build-codex.mjs:1-60`).
  - Frontmatter is normalized to `name` plus `description`. Every other key moves into a sidecar, `references/_claude-frontmatter-extras.yaml`.
  - Descriptions over 1024 characters are truncated at a sentence boundary, and the full text is kept in the sidecar. The change is lossless and reversible.
  - The build runs twice and asserts byte-identical output.
  - `--check` rebuilds into a temp dir and diffs against the committed dist. `--validate` checks the committed dist in place.
  - Both run in `.github/workflows/dist-drift.yml`.
- **Workflow → skill binding check.** `tools/check_workflow_drift.py:1-40` extracts slugs from `Skills:` lines and asserts each one is in `SKILLS.lock`. Two non-slug markers are allowlisted, `none` and `routing`, so real typos still fail.
- **Workflow maturity status.** `WORKFLOWS.lock` gives each workflow a `status: template | validated` plus a sha256. `validated` requires a run record (`workflows/run-records/content-pipeline-prove-gates-run-1.md`).
- **Linter** (`.github/scripts/lint_skills.py`) enforces:
  - name equals the folder
  - a `## The framework` section
  - a `## Reference files` section whose list matches `references/` exactly, in both directions (`:269-307`)
  - backticked cross-skill slugs exist (`:310-343`)
  - SKILL.md ≤500 lines, warning above 400 (`:97-98,346-370`)
  - a generated README catalog (`:373-401`)
  - no em dashes (`:151-163`)
  - no names from a **private brand watchlist** fetched with a token. On fork PRs the check is skipped, and push-to-main is the enforcing backstop (`lint.yml`).
- **Honesty contract as a shared block.** Commit `e5bc675` added an identical "If required data is unavailable" section to the 60 of 103 skills whose output needs data the agent may not get. "A stated gap is a complete answer". Fabricating, estimating or interpolating is "never sanctioned".
- **Content correction waves.** Commits #113-#118 (2026-08-09/10) fixed retired platform features, dead URLs, misattributions and "one fabricated citation". Knowledge skills rot, and someone audits them on purpose.

## 8. wondelai/skills (active)

**What it is.** 65 skills. 14 are metaskills: journeys that orchestrate the others.

**Mechanisms**

- **Metaskill structure.** `CLAUDE.md` "Metaskill Format" lists the sections. Journey Map columns: Phase | Skill | Question | Artifact. Each phase has these fields: Purpose, Brief (fallback), Invoke, Decide with the user, Artifact, Done when.
- **Durable progress tracker.** `docs/<JOURNEY>-PLAN.md` holds phase statuses `pending | in-progress | awaiting-evidence | done | deferred: reason | skipped: reason`, plus Key Decisions and Next Actions (`docs/ARTIFACT-REGISTRY.md:469-490`). Rule 1 (`create-website/SKILL.md:35`): "A journey with a tracker is resumed, never restarted."
- **Phase outputs become shared, typed artifacts.** UPPERCASE files in the user's `docs/` (CUSTOMER.md, POSITIONING.md, …). Section headings form the cross-journey contract. "Extend under these exact headings" (`ARTIFACT-REGISTRY.md:1-12`).

## 13. Reusable skill-catalog validator / index generator: exact algorithms

### 13a. goose-skills `build-index.js`, as implemented

1. `ROOT` = repo root, overridable by `GOOSE_SKILLS_ROOT` for tests (`:21-24`).
2. `TRACKED` = set of `git ls-files` outputs. If git is unavailable, this is `null` and nothing is filtered (`:32-46`).
3. Domains = sorted subdirectories of `skills/` (`:100-107`).
4. For each level in `[capabilities, composites, playbooks]`, for each domain, for each `slug` dir under `skills/<domain>/<level>/`:
   - skip if there is no `SKILL.md`; **throw** if there is no `skill.meta.json` (`:126-129`)
   - parse frontmatter with a line regex `^(\w[\w-]*):\s*(.*)` (**bug: multi-line `>`/`|` values become the literal `">"`**, `:48-64`)
   - `files` = recursive sorted walk, skipping `.tmp`, `__pycache__`, `node_modules`, `.git`, `*.pyc` and `.DS_Store`, and keeping only files in `TRACKED`. Paths are POSIX-normalized (`:73-97`).
   - emit `{slug, name: fm.name||slug, category: level, domain, description: fm.description||'', tags: meta.tags.join(', '), path, files, metadata: meta}`
5. Packs: for each `skills/<domain>/packs/<pack>/pack.meta.json`:
   - each `meta.skills[]` must have a SKILL.md, or **throw**
   - each `meta.registry_skills[]` must resolve to a registry slug, or **throw**
   - existing `shared_files` are kept (`:155-240`)
6. Promote pack-only sub-skills into top-level `skills[]` as `category: capabilities`. **Throw** on a collision with a registry slug, or on the same sub-skill slug appearing in two packs (`:326-374`).
7. Sort skills by slug. Collections: `collection.meta.json` must have `slug == dir`, `installable === false` and ≥1 stage. Each member skill's `metadata.collection_stage` must be one of the declared stages. Every `metadata.collections[]` reference must exist (`:249-391`).
8. **Throw** if any pack slug equals a skill slug (`:394-399`).
9. If `{skills,packs,collections}` is byte-identical to the existing file, keep the old `generated` date (`:403-417`).
10. Write `{version:'1.3.0', generated, skills, packs, collections}` with 2-space JSON and a trailing newline.

### 13b. goose-skills `validate-skills.js`, as implemented

1. Load the schema. Allowed tags and domains come from the schema enums (`:30-35`). Note that it does **not** run full JSON Schema validation, only hand-coded checks.
2. For each domain dir: fail if it is not in the domain enum. Name pre-reorg leftovers specifically (`:62-78`).
3. For each `<domain>/<level>/<slug>`, check:
   - SKILL.md and meta exist and the meta parses
   - `slug` matches `^[a-z0-9-]+$`
   - `meta.slug == dir`
   - `meta.category == level`
   - tags are an array within the enum
   - `installation.base_command` and `installation.supports` are present
   - the slug is globally unique (`:80-140`)
4. Walk every SKILL.md under `skills/`. Every directory must be a `path` in the index's top-level `skills[]`, or fail with the list. A missing index is a failure (`:148-180`).
5. Print every error and exit 1 (`:16-20`).
6. CI order: validate, then build, then `git diff --exit-code skills-index.json`, then unit tests (`ci.yml`).

**Gaps seen in practice:** no description check, which let 105 `">"` entries through; no check that `requires_skills` slugs resolve (none dangle today, by my check); no context-size check.

### 13c. Proposed `cstack check`, combining the best validated pieces

Run in this order. Every step reports all errors, then exits non-zero if there were any. Every counting step fails when its count is zero.

1. **Self-test** (ToB). Build known-bad fixtures in a tempdir. Assert that each rule below rejects its fixture. Assert assertions run ≥ a pinned floor.
2. **Discover**. Walk `skills/**/SKILL.md(.tmpl)`, using `git ls-files` only (goose). The skill count must be greater than 0.
3. **Parse** frontmatter and meta with a real YAML or JSON parser (qm, ToB, gstack `skill-check.ts:24-40`). Then check:
   - name equals the directory, and the slug regex matches
   - description is a non-empty string, ≤1024 characters, and contains trigger plus boundary phrases (higgsfield)
   - level matches folder (goose)
   - required section-24 contract fields are present
4. **Uniqueness**. Check uniqueness across skills, packs and workflows (goose `:136-139`, `:394-399`).
5. **Resolve references**:
   - `references/*` links both ways (higgsfield, rampstack)
   - backticked or `requires`/`handoff` slugs against the discovered set (rampstack)

## cstack implications (summary)

- **Borrow the CI skeleton whole.** Combine: goose's index generator, tree ⊆ index check and freshness diff; rampstack's sha256 lockfile and `--check` rebuild; higgsfield's reference-orphan, version-sync and description-phrase checks; ToB's self-test floor and zero-items-fail rule; gstack's placeholder throws, untracked-file check and context ratchet. Section 13c gives the order.
- **Borrow the provider adapter from goose and Superside, keeping each one's good half.**
  - goose: idempotency digest, persisted pending jobs, never resubmit on timeout.
  - Superside: transient-only retry allowlist, size audit, dated cost table with explicit "unpriced" entries.
  - Do not borrow Superside's sync-disconnect retry. Persist the ledger to disk.
- **Borrow brand-state mechanics from higgsfield and Taste.**
  - higgsfield: revisioned slots, dependency invalidation, authoritative user values, atomic writes.
  - Taste: cite every value, build only from the structured file, run an external verifier with a 2-round cap.
- **Borrow workflow mechanics from wondel and rampstack.** wondel: durable PLAN tracker, typed shared artifacts, resume-not-restart. rampstack: template vs validated status gated on run records, and the honesty contract (placed once in the preamble).
- **Borrow platform rules from qm.** Durable by default; one AGENTS.md; provenance-tagged memory; capabilities from registry metadata, never model names; pinned upgrades.
- **Do not borrow:**
  - hand-rolled YAML parsing
  - hand-synced vendored helper copies
  - name-sniffed model behaviour
  - rules that live only in prose
  - multiplying one block of text across 60 files
