# 3D for brand work: models, runtimes, pipelines and best flows (snapshot 2026-10-03)

**Answer first.** For product 3D, the generative model is almost never the hard part. The hard part is *product truth* (silhouette, proportions, label and print), staying inside a *web budget* (bytes, LCP, GPU), and choosing *real 3D vs fake 3D* for the outcome.

The default rules:

- **Real product, label must be exact.** Build the geometry deterministically (CAD/dieline/photogrammetry, or a generated mesh used only as a shape draft). Apply the label as the official artwork texture. Never let a model paint the text.
- **Rotating hero on the web.** Use a compressed GLB (Draco or Meshopt plus KTX2/WebP) in three.js/R3F or `<model-viewer>`, with a static poster as the LCP element. Use a WebP image sequence when the motion is fixed and the look must be offline-render quality.
- **Social turntable.** Render a real turntable from the 3D asset (Blender/KeyShot), or animate approved stills with image-to-video. Image-to-video drifts on labels, so check it frame by frame.
- **AR.** Serve a GLB for Android/WebXR and a USDZ for iOS Quick Look from the same source asset.

Method: WebSearch to find primary URLs, then WebFetch on vendor docs, model pages, repos and dated articles. WebFetch returns a model-written summary, not raw HTML, so numbers that matter are marked with confidence. Evidence labels: **observed** (I ran or saw it), **documented** (vendor docs or repo), **marketing** (vendor claim), **inferred** (my reasoning). Every access date is 2026-10-03 unless a row says otherwise. Observed 3D builds of the owner's reference site are in a gitignored private note. The site could not be reached from this session (egress policy denial), so no claim about it is made anywhere.

**Product-fidelity limits** (inferred from how these models work, and consistent with every vendor demo seen):

1. Text and fine print come out as smeared texture. The texture is re-synthesised, not projected.
2. Thin parts (straps, caps, handles) and transparent or refractive materials (glass, liquids) fail or come out solid.
3. Back and side views are hallucinated from a single image. Multi-view input helps but does not guarantee anything.
4. Proportions drift and scale is arbitrary unless you set it (`auto_size`, or fix it in Blender from known dimensions).
5. The topology is triangle soup unless you ask for quad or remesh. Fine for web display, bad for editing or deforming.

So treat generated meshes as **shape drafts or background props**, never as the hero SKU's truth.

## 5. Asset pipeline (deterministic, cheap, scriptable)

| Step | Tool | Gate |
|---|---|---|
| Inspect | `gltf-transform inspect in.glb` (geometry-heavy, texture-heavy, or too many draw calls) | report written |
| Clean | `weld`, `dedup`, `prune`, `simplify` (meshopt simplifier) | triangle budget |
| Compress geometry | `draco` or `meshopt` (Meshopt decodes faster; Draco is often smaller) | file size |
| Compress textures | `etc1s` (colour) and `uastc` (normals) → KTX2, or `webp`; `resize` to ≤2048² | texture budget |
| One-shot | `gltf-transform optimize in.glb out.glb --compress draco --texture-compress webp` (defaults do not fit every scene, so inspect first) | — |
| AR iOS | USDZ via Reality Converter / Reality Composer / usdzconvert, Blender USD export, or Meshy's USDZ output. Link with `<a rel="ar" href="x.usdz">` or `ios-src` | opens in Quick Look on a device |
| Validate | Khronos glTF Validator; Khronos 3D Commerce Asset Creation Guidelines 2.0 (2025-08-07) and the community 3DC validator (`@mikefesta/3dc-validator`) | no errors |

Sources: https://gltf-transform.dev/cli ; https://developer.apple.com/augmented-reality/quick-look/ ; https://www.khronos.org/news/permalink/introducing-asset-creation-guidelines-2.0-for-commerce-ready-gltf-assets ; https://cdn.jsdelivr.net/npm/@mikefesta/3dc-validator@1.0.0/README.md.

**Commerce budget (documented, Shopify Partners checklist).** Total file about **4 MB**, textures ≤ **2048×2048** for mobile web, GLB as the primary format, PBR with ORM packed into R/G/B, **real-world scale**, origin at the **centre of the product's base**, USDZ when needed (https://help.shopify.com/partners/resources/creating-3d-models/3d-model-standards-checklist).

## 6. Product renders and DCC

- **Blender (Cycles/EEVEE)** is free, scriptable and agent-reachable through Blender MCP.
- What works through Blender MCP: primitives, Principled BSDF materials, lights, product-viz backdrops, batch ops.
- What fails through Blender MCP: organic modelling, rigging, node graphs beyond a few nodes (Geometry Nodes is "brittle"), precise spatial relations. In the reviewer's words, it is a "rapid prototyping tool rather than a modeling replacement" (documented, practitioner review 2026-05-06: https://www.mindstudio.ai/blog/claude-blender-mcp-real-world-performance).
- **KeyShot** and **NVIDIA Omniverse** are the incumbent product-render tools. Neither was found to have an agent interface in this pass (unverified). They are human-operated in cstack.
- So the agent's real leverage is **scene setup, camera rigs, turntable automation, batch renders and export**, with the hero geometry and label coming from truth sources.

## 8. Best flows by outcome (decision tree)

```text
Is the subject a REAL product whose label/print must be exact?
├─ yes → truth source exists?  CAD/dieline ─▶ T1   photos only ─▶ T2 (capture) or T3 (hybrid)
└─ no (concept, prop, abstract object, symbol) ─▶ G (generative)
Then pick the OUTPUT:
  web hero (rotate/scroll) ─▶ Flow A    packshot stills ─▶ Flow B
  social turntable video   ─▶ Flow C    AR view         ─▶ Flow D
```

**Truth paths (geometry + label).**
- **T1 (CAD/dieline, deterministic).** Import into Blender → real-world scale, origin at base → UV the label island → apply the **official** artwork (`assets/official/`) as the base colour → PBR from measured references.
- **T2 (capture).** 40–200 photos, even light, turntable → Object Capture / Polycam / KIRI → mesh clean-up. Or splats for a photoreal web view with no relighting.
- **T3 (hybrid).** Generated mesh from multi-view photos (Hunyuan multi-view $0.525, Tripo multiview, Rodin multi-image) used only for *shape* → remesh → replace the generated texture on label areas with the official artwork → fix proportions from the known dimensions.
- **G (generative).** Text/image → mesh probes on the cheapest model (TRELLIS.2 512p $0.25 or Hunyuan $0.375) → pick one → re-run only that one on the premium model (Rodin $0.40+ / Meshy $1.20) → remesh to budget.

**Flow A: rotating or scroll-linked hero on the web.**

1. Pick the branch. Interactive or real-time (rotate/drag/configure) → **A1 GLB**. Fixed choreography at render quality → **A2 image sequence**. Designer wants to author it → **A3 Spline** (MCP when available), exported to R3F.
2. A1 pipeline: truth path → Blender scene (camera, env HDRI from Poly Haven) → `gltf-transform` inspect/optimize → R3F/three.js or `<model-viewer>` with `poster` → scroll binding (GSAP ScrollTrigger / drei `ScrollControls`) → device-tier fallback to the poster.
3. A2 pipeline: render N frames from the truth asset in Blender (deterministic and label-safe), or keyframes plus image-to-video (generative; check the label per frame) → WebP q≈85 ≤150 frames → canvas scrubber with preload and poster.
4. Gates: GLB ≤ 2.5 MB, ≤ 100k triangles, textures ≤ 2k; LCP element is the poster; no long tasks > 200 ms on mid-tier mobile (`cstack browse qa` plus a Lighthouse run); label overlay check on 4 canonical angles (render vs official artwork); 375/768/1440 screenshots.
5. Failure modes: an un-compressed 30 MB GLB; canvas as the LCP element; env map heavier than the model; generated texture standing in for the label; scroll-jacking that breaks accessibility (respect `prefers-reduced-motion`; give a static alternative).

**Flow B: 3D packshot stills.**

1. Truth path → Blender scene from the brand's photography rules (lens, light ratio, backdrop tokens) → render a contact sheet at low samples → owner picks → final renders → composite official marks.
2. Optional generative finish: render a clean plate, then an image-edit model for environment or atmosphere *only*, with the product masked and locked (existing `image-edit` / `product-fidelity` discipline).
3. Gates: silhouette IoU against a reference photo; label OCR plus pixel diff against the official artwork; colour ΔE on brand swatches.
4. Cost: the deterministic render costs electricity. The paid step is only the optional finish.

**Flow C: turntable video for social.**

1. **C1 (default, deterministic).** Blender turntable from the truth asset (360° in 4–8 s, 1080×1920 and 1080×1080) → ffmpeg encode → optional generative background via a masked composite.
2. **C2 (generative, fast).** An approved still → image-to-video orbit (models from the `model-router` video rows). Check every Nth frame for label drift and geometry melt, and stop after 2 failed probes.
3. **C3.** A splat flythrough rendered from three.js/SuperSplat for a photoreal "scan" aesthetic.
4. Gates: frame-sampled label check, loop seam check, platform specs.

**Flow D: AR view.**

1. The single source asset from Flow A1 → GLB (Android Scene Viewer/WebXR) plus USDZ (iOS Quick Look) → `<model-viewer ar ar-modes="webxr scene-viewer quick-look" ios-src=...>` or Shopify 3D media.
2. Gates: real-world scale (place it next to a known object in AR), origin at the base, ≤ 4 MB, opens on a real iOS and a real Android device (owner step).

## 9. cstack implications

**Skills (proposed; all follow the contract headings and PREAMBLE).**

1. **`three-d`** (Make). Contract:
   - Inputs: outcome (web-hero | packshot | turntable | ar | prop), truth source (cad | dieline | photos | none), product entity, budget.
   - Missing input: no truth source plus a real label means STOP and ask. Never route to G.
   - Process: classify with the §8 tree → pick a branch → plan steps with deterministic and generative steps marked → `cstack spend plan` for paid gens → run → gates → handoff.
   - Outputs: `work/3d/<id>/` with `source/`, `model.glb`, `model.usdz`, `poster.avif`, `frames/`, `inspect.json`, `.gen.json` sidecars, `report.md`.
   - Failure modes: generated label, unbounded GLB, scale unknown, a hallucinated back view presented as truth.
   - Hands off to: `product-fidelity` (lock), `generate-media` (gens), `brand-verify` (gates), `creative-review`.
2. **`web-3d`** (Make/Build). Turns a GLB or frame set into a hero component (R3F, `<model-viewer>`, or a canvas sequence) with poster, fallback, reduced-motion and the budgets. Loads a `references/web-3d-rules.md` distilled from the three/R3F rule sets above (cite and respect licences). Handoff to `browse qa`.
3. Extend **`product-fidelity`** with a `3d` section: label UV-island audit, 4-angle overlay, a dimension check against the PRODUCT entity.
4. Extend **`model-router`**: `--modality 3d` rows and a rule that **real product + label → never generative texture**.

**Workflow.** `workflows/product-3d` (template):

```text
brief → product-fidelity (lock entity, collect truth source) → three-d (branch + plan)
→ [owner gate: branch + spend] → three-d build → web-3d (if web) → brand-verify
→ creative-review → [owner gate] → learn
```

Add an optional `3d-hero` step to `workflows/landing-page` that calls `web-3d` when the brief asks for a rotating object.
